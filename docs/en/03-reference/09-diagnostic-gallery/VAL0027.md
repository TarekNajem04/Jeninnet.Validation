# VAL0027 — Sanitize cannot be applied

| Field | Value |
|---|---|
| Severity | `Error` |
| Code fix | Intentional — see below |
| Constitution principle | II. Declarative-First |

Sanitization writes the cleaned value back in place, but the member has no writable setter or is not a supported sanitizable type.

## Triggering code

```csharp
public sealed class Order
{
    [Sanitize(Trim = true)]
    public string Code { get; init; } = string.Empty;
}
```

## Compiler output

```text
error VAL0027: [Sanitize] cannot be applied to "Code": the member has an init-only setter
```

## Why there is no automatic fix

Fixing the member setter or removing sanitization is a design decision; the generator cannot mutate an immutable member.

## How to fix it

Give the member an accessible non-init setter, sanitize a writable copy, or remove the attribute. The fluent equivalent without a setter throws InvalidOperationException at configuration time.
