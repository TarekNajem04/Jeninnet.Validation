# VAL0003 — Rule parameter type mismatch

| Field | Value |
|---|---|
| Severity | `Error` |
| Code fix | Intentional — see below |
| Constitution principle | II. Declarative-First |

The rule parameter has a different type from the value it must compare. The generator cannot choose between converting the parameter and changing the rule.

## Triggering code

```csharp
[Validate]
public sealed class User
{
    [InclusiveBetween("18", "99")]
    public int Age { get; set; }
}
```

## Compiler output

```text
error VAL0003: Rule "InclusiveBetween" expects a parameter of type "Int32", but received "String"
```

## Why there is no automatic fix

The literal or the rule may be wrong; the intended change is ambiguous and no safe automatic rewrite exists.

## How to fix it

Pass numeric literals for numeric members: [InclusiveBetween(18, 99)]. Use the literal type that matches the member, not a string that happens to look numeric.
