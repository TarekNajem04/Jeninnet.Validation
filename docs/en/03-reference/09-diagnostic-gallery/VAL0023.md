# VAL0023 — RuleFor member name mismatch

| Field | Value |
|---|---|
| Severity | `Warning` |
| Code fix | Available — Rewrites the member-name argument to nameof(Model.Member). |
| Constitution principle | III. Compile-Time Safe & Diagnostic-Rich |

The RuleFor expression selects one member but the string argument names another. The generated error path and client payload would be wrong.

## Triggering code

```csharp
public sealed class Customer
{
    public string? Name { get; set; }
}

public sealed class CustomerValidator : Validator<Customer>
{
    protected override void Configure(ValidatorRuleBuilder<Customer> builder)
    {
        builder.RuleFor(static x => x.Name, "Email").NotEmpty();
    }
}
```

## Compiler output

```text
warning VAL0023: RuleFor selects member "Name" but passes member name "Email"; use nameof(Customer.Name) or "Name"
```

## Fix

Rewrites the member-name argument to nameof(Model.Member).

## Fixed code

```csharp
public sealed class Customer
{
    public string? Name { get; set; }
}

public sealed class CustomerValidator : Validator<Customer>
{
    protected override void Configure(ValidatorRuleBuilder<Customer> builder)
    {
        builder.RuleFor(static x => x.Name, nameof(Customer.Name)).NotEmpty();
    }
}
```

## Why this is the fix

Use nameof so the compiler keeps the expression and the reported member aligned. Custom paths and free-form names are intentionally not rewritten.
