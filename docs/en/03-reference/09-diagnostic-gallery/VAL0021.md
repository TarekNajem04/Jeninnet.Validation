# VAL0021 — Invalid date/time rule value

| Field | Value |
|---|---|
| Severity | `Error` |
| Code fix | Intentional — see below |
| Constitution principle | III. Compile-Time Safe & Diagnostic-Rich |

A date/time rule literal cannot be parsed as the member's date/time type under the invariant culture.

## Triggering code

```csharp
[Validate]
public sealed class Subscription
{
    [After("not-a-date")]
    public DateOnly StartsOn { get; set; }
}
```

## Compiler output

```text
error VAL0021: The value "not-a-date" cannot be parsed as type "DateOnly" for the date/time rule on "StartsOn"
```

## Why there is no automatic fix

The literal is unparseable; the intended date is unknown and the generator never substitutes DateTime.Now.

## How to fix it

Use an invariant date/time literal for the member type, for example [After("2026-01-01")] on DateOnly. If the source is local time, normalize it at the boundary.
