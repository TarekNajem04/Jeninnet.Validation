# VAL0010 — Rule parameter out of range

| Field | Value |
|---|---|
| Severity | `Error` |
| Code fix | Available — Swaps the reversed InclusiveBetween bounds. |
| Constitution principle | III. Compile-Time Safe & Diagnostic-Rich |

A range rule has its lower bound above its upper bound, so no value can satisfy it.

## Triggering code

```csharp
[Validate]
public sealed class User
{
    [InclusiveBetween(10, 1)]
    public int Score { get; set; }
}
```

## Compiler output

```text
error VAL0010: Parameter "10" for rule "InclusiveBetween" is outside the valid range for type "Int32"
```

## Fix

Swaps the reversed InclusiveBetween bounds.

## Fixed code

```csharp
[Validate]
public sealed class User
{
    [InclusiveBetween(1, 10)]
    public int Score { get; set; }
}
```

## Why this is the fix

Write bounds in lower-to-upper order. If the intended order is semantically meaningful, rename or restructure the rule instead of relying on the fix.
