# VAL0032 — Relative date rule requires a date/time member

| Field | Value |
|---|---|
| Severity | `Error` |
| Code fix | Intentional — see below |
| Constitution principle | II. Declarative-First |

[FutureDate] and [PastDate] compare a member with the current instant, so the member must have a date/time type.

## Triggering code

```csharp
[Validate]
public sealed class Subscription
{
    [FutureDate]
    public string? When { get; set; }
}
```

## Compiler output

```text
error VAL0032: [FutureDate] on "When" requires DateTime, DateTimeOffset, or DateOnly; "string" is not supported
```

## Why there is no automatic fix

The member type or the rule must change based on intent; TimeOnly has no date component and is not a substitute.

## How to fix it

Use DateTime, DateTimeOffset, or DateOnly for the member, or use a custom/fluent rule for another representation.
