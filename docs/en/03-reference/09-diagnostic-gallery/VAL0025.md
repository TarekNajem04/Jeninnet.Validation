# VAL0025 — Async-only validator in synchronous adapter

| Field | Value |
|---|---|
| Severity | `Warning` |
| Code fix | Intentional — see below |
| Constitution principle | III. Compile-Time Safe & Diagnostic-Rich |

A [JeninnetValidatable] adapter points at an async-only validator, but the DataAnnotations adapter calls the synchronous Validate API.

## Triggering code

```csharp
[AsyncOnlyValidator]
public sealed class AsyncOrderValidator : Validator<Order>
{
    protected override void Configure(ValidatorRuleBuilder<Order> builder)
    {
        builder.RuleFor(static x => x.Number, nameof(Order.Number))
               .Must(static async (value, token) =>
               {
                   await Task.Yield();
                   return value is not null;
               });
    }
}

[JeninnetValidatable(typeof(AsyncOrderValidator))]
public sealed class Order
{
    public string? Number { get; set; }
}
```

## Compiler output

```text
warning VAL0025: Validator "AsyncOrderValidator" is marked [AsyncOnlyValidator] but "Order" calls the synchronous DataAnnotations path; use an async integration path or add a synchronous rule
```

## Why there is no automatic fix

The integration path or the validator must change based on intent; the adapter cannot silently switch to an async contract.

## How to fix it

Use an async integration path, or add a synchronous rule to the validator so the DataAnnotations path can run it.
