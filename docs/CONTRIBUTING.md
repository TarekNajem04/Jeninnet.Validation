# Contributing to the Documentation

This guide covers documentation changes for the Jeninnet.Validation book.

## Where a change belongs

| Content | Location |
|---|---|
| First steps, installation, mental model | `docs/en/01-getting-started/` |
| Task-oriented guides and integrations | `docs/en/02-guides/` |
| Architecture, API, rules, diagnostics, compatibility | `docs/en/03-reference/` |
| Performance, AOT, quality, troubleshooting | `docs/en/04-operations/` |
| Glossary, package map, samples | `docs/en/appendix/` |
| Repository-level claims | `README.md`, `ROADMAP.md` |

## Chapter structure

Each chapter should contain:

1. A level-1 title.
2. A short purpose statement.
3. Prerequisites when needed.
4. Task-oriented sections with runnable code examples.
5. Verification steps (how the reader knows it worked).
6. Related links using relative paths.

## Code examples

- Examples must compile against the code in this repository.
- Prefer examples backed by a sample under `samples/` or a test under `tests/`; name the backing
  project in the text.
- Do not invent APIs; verify member names against `src/` or the referenced package.
- Keep examples small and complete enough to run.

## Package and README rules

- Package READMEs are shipped on NuGet; use absolute links to repository docs.
- The repository README states the current package count and sample count; update it with any
  package or sample change.
- Do not link to internal, unpublished documents.
- Every packable project ships the shared icon (`assets/jeninnet-validation-icon-128.png`,
  wired centrally in `Directory.Build.props`); do not add per-package icons. SourceLink is wired
  centrally too and stays on for CI builds only, so local builds without a git remote stay
  warning-free.
- The preview release notes (`.github/release-notes/v<version>.md`) list every packable
  package; the `PackagingBaselineTests` suite fails when the count or the list drifts.

## Public API documentation and baselines

- API pages are generated by DocFX from XML documentation. `docs/en/03-reference/08-api-reference.md`
  is the curated namespace map; do not duplicate generated member documentation by hand.
- Every packable project commits `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt` next to its
  `.csproj`. New API goes to `Unshipped`; stale entries fail the build with `RS0017`.
- Read the [public-API workflow](../scripts/api/README.md) before adding, removing, or renaming a
  public type or member. Breaking changes require the obsolete/major policy in
  [Compatibility and versions](en/03-reference/06-compatibility-and-versions.md).
- Add every new packable project to `docs/docfx.json`; the architecture test and the API-reference
  check fail when a package is missing.
- Do not edit `docs/api/` or `docs/_site/`; both are generated and git-ignored.

## Message keys

- `ValidationMessageKeys` is the single source of truth. Adding a key means adding the constant
  **and** the entry in every `Resources/*.json` pack (all 40 cultures); removing a key means
  removing both.
- Custom keys (rule-template names, caller-supplied codes, resx keys) stay outside the catalog.
  Only a pack entry that is deliberate without a constant belongs in
  `src/Jeninnet.Validation.Localization/MessageKeyAllowList.json`; remove the entry when the
  transition ends.
- Run `pwsh scripts/localization/check-message-keys.ps1` before opening a change; it fails on a
  missing entry, an extra entry, or a stale allow-list entry.
- Adding a language follows the package README checklist (copy `en.json`, translate every value,
  keep every key and placeholder, native-speaker review).

## Checks

Run the documentation checks before opening a change:

```powershell
pwsh scripts/docs/check-doc-links.ps1
pwsh scripts/docs/check-readme-claims.ps1
pwsh scripts/docs/check-arabic-text.ps1
pwsh scripts/api/check-public-api-baselines.ps1
pwsh scripts/localization/check-message-keys.ps1
```

For API-reference changes, generate the metadata first:

```powershell
dotnet tool restore
dotnet docfx metadata docs/docfx.json --warningsAsErrors
dotnet docfx build docs/docfx.json --warningsAsErrors
pwsh scripts/docs/check-api-reference.ps1
```

The full build and test gates are listed in `CONTRIBUTING.md`.
